## 2. 調査の4層構造

評価は必ず次の4層で構成し、層をまたいで混ぜない。

1. **権利・尊厳への影響**：加入・退会・役員就任の意思、家庭事情のプライバシー、子どもの平等な取扱い、不利益の有無。人権侵害を事実未確認のまま自動認定しない。
2. **一次資料に基づく固定12評価軸**：学校×年度×観察項目の事実状態。YESは行為や制度の存在を示すだけで、適法・違法を意味しない。
3. **教育委員会・学校・PTAの責任主体の分離**：教育委員会の制度設計・通知・指示・監督、学校・校長・教職員の実施、PTA自身の内部決定・事務を分ける。単独責任を憶測で決めない。制度の制定者が不明、教育委員会の指示が確認できない、学校での実施が不明な場合は、それぞれ「未確認」と記録し、誰か一人の責任に推測で集約しない。
4. **法的評価と具体的是正**：具体的な所掌事務、権限、適用法令、反証、是正すべき行為と担当主体を明示する。

成果物では、この4層それぞれを**別の記述**として置く。第2層の件数を第1層の人権侵害発生率や第4層の違法率に読み替えない。

## 3. 法的検討の絶対順序（省略・逆順禁止）

1. **主体の分離**：公立学校・教育委員会は公的主体、PTAは独立した任意加入の私的団体。
2. **事務の帰属**：入退会、会費徴収・未納管理、役員選出、団体会計などは原則としてPTAの内部事務。
3. **学校側の具体的な公法上の権限**：学校・校長・教職員がその事務を公務としてできる法令上の所掌事務・授権を特定する。例外の有無も調査する。学校徴収金規程、校長裁量、校務分掌、PTAからの委任、本人同意、職務専念義務免除、長年の慣行だけを権限の代用品にしない。
4. **個人情報**：上記の所掌事務を検証した後で、個人情報保護法61条の利用目的の特定・保有の必要性、69条の利用・提供の制限、必要なら例外事由を検討する。「同意があるか」から分析を始めない。
5. **適用と結論の分離**：「法令・内部規程がある」「その規定が当該事務に適用される」「具体的行為が適法」は別問題。根拠未確認は明記する。**主体が異なるという理由だけで即違法と断定しない。** 別団体だから直ちに違法とはせず、例外的な法令上の根拠と反対解釈を確認する。是正を求める主体と行為を特定する。

必要に応じて地方自治法235条の4第2項（市が所有しない現金の保管等）、地方公務員法の服務、契約の成立、教育委員会の権限を個別検討。条文の適用範囲や最新の原文はその都度一次資料で確認する。

**235条の4第2項に関する実務上の注意（大崎市の一次資料で確認済み）**：大崎市立小中学校徴収金事務取扱規程第12条第3号は「学校徴収金（学校会計団体の会費を除く）の預金名義人は校長とし、開設に使用する印鑑は職印とする」と定める（出典：学校教育課開示文書 `3-1_大崎市立小中学校徴収金事務取扱規程.pdf` p.3、2026年11月15日直接確認）。すなわち団体費＝PTA会費等の預金名義は規程上明示的に除外されており、学校・自治体が当該現金の保管主体であることは規程から当然には導けない。この条文を使う場合は、口座名義・金融機関との契約主体・受領と送金の事実を資料で押さえてからにする。規程が除外していることを確認せずに235条の4第2項を主要論点に置かない。

全対象校に12項目を必ず適用し、**不明なら「問題なし」ではなく `unknown`**。YESは有利な制度も懸念ある行為も含む。たとえば軸1「任意加入の明示」は望ましい方向の記載、軸5「学校によるPTA会費徴収」は権限確認を要する行為の記載であり、**同じ方向の点数に変換しない**。合計点数で違法ランキングを作らない。軸の増減・定義変更には版改訂と既存データの再検証が必要。

観察値は次の6種類のみ（スキーマの `status` enum と同一）：

- `confirmed_yes`：直接確認した一次資料が、その学校・対象年度における対象事実を明示する。評価や違法判定ではなく、**行為／制度の存在の確認**。
- `confirmed_no`：直接確認した一次資料が、対象事実の不存在や採用していない旨を**明示**する。無記載・未収集・取得不能・単なる欠席は該当しない。
- `indication`：断片情報・二次資料・疑義などの示唆はあるが、直接の一次資料で確定できない。
- `unknown`：確認材料不足、調査未了、年代不一致。
- `not_applicable`：校種・制度等の理由で適用対象外と**当該年度の一次資料を直接確認**でき、理由がある。資料IDだけでは不可。
- `conflicting`：当該年度の**直接確認済み一次資料を異なる2件以上**保持し、相反する内容とその出典位置を記録して、どちらかへ勝手に収束しない。機械検査は資料の相反性そのものまでは保証しない。

**`confirmed_no` にはスキーマ上の追加要件がある。** 検証器は軸オブジェクトに `explicitNegative: true` がないと `NEGATIVE_NOT_EXPLICIT`（「must document explicit negative, not mere absence」）で不合格にする。このフィールドは `report-dataset.schema.json` の required には現れないので見落としやすい。資料の欠落で `confirmed_no` を付けさせないための歯止めであり、立てる前に「当該年度の原本が反対の取扱いを明示しているか」をもう一度確かめる。`conflicting` には出典IDが2件以上かつ直接確認済み一次資料が2件以上必要（`CONFLICT_TOO_FEW_SOURCES`／`CONFLICT_NOT_VERIFIED`）。

**適法・違法の二択ではない。** 法的リスク評価には別途、制度上の権限と具体的行為の詳細調査が必要。

## 5. 入会申込書等の「文書存否」独立台帳

**最重要の規則：文書が提出資料中に存在しない事実を曖昧な「未確認」に埋没させない。ただし提出されなかったことと、学校やPTAにも保有がないことを同一視しない。**

12軸は「運用・行為」の観察、文書存否台帳は「証拠文書の提出・保有・不存在決定」の記録。**両者は別データ**であり、書類が開示資料になかっただけで12軸の `confirmed_no` を付けない。文書存否は現行スキーマ `report-dataset.schema.json` の管理対象外であり、**別ファイルで持つ**（§13-2）。

少なくとも次の段階を区別：

1. **開示資料中に確認できない**：調査報告書などが特定校の提出資料中に当該文書を確認できないと明記。
2. **文書名一覧に独立書類の記載がない**：目録の題名にない。ただし別のPDF内部の様式・記述までは否定していない。
3. **文書存否の個別照合が未了**：その学校について未調査。存在するとも不存在ともいわない。
4. **行政が保有不存在を正式に決定**：該当書類・対象年度・保有機関・決定文書を直接確認したときに限る。市教委が保有しないことは、PTAが保有しないこととは異なる。
5. **個人情報等により不開示**：保有の有無と公開できない理由を分離（正式決定に基づく）。不開示を不存在と表現しない。

存否調査の対象文書10種（`data/osaki-document-existence-2026.json` の `documentTypes` と同一）：①PTA入会申込書、②入会意思・承諾の記録、③退会届・退会規定、④PTA会員名簿、⑤個人情報利用・提供の同意書、⑥役員選出の同意書・委任状、⑦役員免除申請書・判断記録、⑧PTA会費収納の委任契約書、⑨学校による会費徴収の公法上の根拠文書、⑩口座名義・収納契約・資金フロー記録。

**到達目標の管理項目**：各文書を `学校ID／年度／文書種類／請求対象／保有主体／提出有無／開示決定の種別／証拠IDとページ／確認日／反証` で管理する。新しい自治体に展開するときもこの構造で記録する。学校やPTAが「書類は存在する」と説明した場合は、文書名・作成日・保有部署・適用年度・該当箇所を特定して照合する。*提出されなかったという事実を明確に書き、根拠のない全面的不存在の断定は行わない*。

**現行実装の実際**：`data/osaki-document-existence-2026.json`（**mainに反映済み**）は上記の到達目標より粗い。実装フィールドは次のとおりで、10種のうち2種しか学校別に展開されていない。

- トップレベル：`title` / `reviewDate` / `scope` / `source` / `statusDefinitions` / `documentTypes`（10種を文字列配列で列挙）/ `schools`
- `source`：`title`「大崎市立小中学校PTA関係文書 調査報告書」/ `date` 2026-11-15 / `evidencePages`「PDF第5章および付録B、田尻中学校の目録（PDF43〜45頁）」/ `totalDisclosedDocuments` 220 / `totalDisclosedPages` 983
- 学校レコード：`id` / `name` / `applicationForm` / `withdrawalRule` / `documentScope` のみ。年度・保有主体・証拠ID・確認日・反証のフィールドは**ない**。
- `statusDefinitions` の3値：`not_found_in_disclosure_report`（報告書が「開示資料中に確認できない」と明記）／`not_listed_as_standalone_in_24_disclosed_titles`（田尻中の開示24件の題名目録に独立書類として記載なし）／`not_assessed`（当該文書の提出・保有の存否を独立確認できていない）。正式な行政の不存在決定を表す値は定義されておらず、登録事例もない。

2026-11-15時点の内訳（25校）：**6校**（古川第二小・古川第三小・古川北小・古川北中・古川東中・鳴子小中）が `not_found_in_disclosure_report`、**田尻中1校**が `not_listed_as_standalone_in_24_disclosed_titles`、**残り18校**が `not_assessed`。

次の自治体に展開するときは、この粗い2フィールド構造を踏襲せず、10種×学校×年度の行で記録すること。大崎市の既存ファイルを上書き変換する場合は、旧ファイルの値と対応関係を残し、公開ページの表示と齟齬が出ないかを確認する（§11）。

## 6. 原資料台帳・母集団・集計

### 6.1 原資料台帳

原資料ごとに `sourceId／発行主体／日付／対象年度／文書名／原本URLまたは非公開パス／該当頁／原本の直接確認日／公表・匿名化の可否` を記録。スキーマの必須項目は `id`・`title`・`issuer`・`kind`・`documentDate`・`targetYear`・`url`・`filePath`・`verification`・`verifiedAt`・`publicationLinkChecked`・`containsPersonalData`・`redactionChecked`。`kind` は `primary`／`secondary`／`internal`、`verification` は `direct_checked`／`metadata_only`／`unavailable`。

検索結果、ファイル名、OCRだけで断定しない。`metadata_only` の資料から内容を推測しない。Google Driveの「全国資料」リンクは公開原本目録の候補にすぎず、PCローカルの同名フォルダと同一と推定しない。画像だけで全文を確認したと誤記しない。公開用には非公開のDrive URL、ローカルパス、児童・保護者の氏名、個人情報、署名・印影等を転記しない。

### 6.2 母集団

自治体の全設置校・校種・統廃合を自治体公式一覧で確定し、`scope.totalPublicSchools`、`scope.populationSourceId`、`scope.populationSchoolIds`、`scope.sampling`（`census`／`selected`）、`scope.scopeNote`、`scope.schoolTypes`、`scope.targetYears` を固定。各学校レコードの `schoolType` は `小学校`／`中学校`／`義務教育学校`／`高等学校`／`特別支援学校`／`その他` の6値のみ。**資料収集校数、直接判定できた校数、全設置校数を混同しない。** 未取得校も12軸すべて `unknown` として登録する。同一校・旧名称・統廃合・年度違いを重複集計しない。

全数調査は学校数の一致だけでなく、登録した全設置校IDと各学校レコードの集合一致を**機械検査**する。抽出調査でも学校IDは固定した母集団内のものに限る。年度が合わない資料は判定不可能とする。母集団の出典資料は `kind: primary` かつ `verification: direct_checked` でなければ検証器が `POPULATION_NOT_VERIFIED` で落とす。

### 6.3 集計

各軸で `N=対象学校数`、`Y=confirmed_yes`、`NO=confirmed_no`、`I=indication`、`U=unknown`、`NA=not_applicable`、`C=conflicting` としたとき：

- `Y+NO+I+U+NA+C=N` を検証器が強制する（不一致は `AXIS_SUM` で不合格）。
- **全対象校に占める確認YES率** `Y/N×100`（最低限確認された比率であり、実態率の推定ではない）。
- **判定可能校に占めるYES率** `Y/(Y+NO)×100`。`Y+NO=0` は `null`＝**算定不能**（0%ではない）。
- **判定可能率** `(Y+NO)/N×100`。
- `indication`、`unknown`、`not_applicable`、`conflicting` は判定可能校の分母に入れない。
- 標本抽出や公開資料限定の調査では「全校の割合」ではなく**調査対象校の割合**と記載し、選択バイアスと回収状況を注記。
- 学校規模で加重しない。児童数・保護者数・文書数の割合と学校数の割合を混同しない。割合は小数1位、学校数ベース。法令違反率・人権侵害発生率として表示しない。

集計は人手の暗算を正本とせず、検証器の `metrics.json` に一致させる。検証器が出すフィールド名は固定で、自治体ごとに言い換えない：トップに `schemaVersion`・`reportId`・`asOf`・`municipality`・`totalPublicSchools`・`targetSchools`・`sampling`・`coverageOfAllPublicSchoolsPct`・`axes`、軸ごとに `id`・`label`・`denominatorTargetSchools`・6状態の件数・`confirmedKnownDenominator`・`confirmedYesOfTargetPct`・`confirmedYesOfKnownPct`・`confirmedCoveragePct`。入力JSONに算出済み割合を書かない。

## 8. 納品と品質ゲート

各自治体の成果物は、少なくとも次のもの：

- 全校・12軸・原資料参照付き `dataset.json` と検証器出力 `metrics.json`。
- 自治体総合報告書、学校別評価書、出典目録。
- **文書種類別存否台帳**（12軸データとは別ファイル）。
- 権利・尊厳への影響、3主体の責任、法的評価の別々の記述。
- 地図用データ、既存サイトへの遷移・URL計画、検証・審査ログ、レビュー記録。
- 資料未取得校も `unknown` で登録。途中段階は「暫定」と明記し「完成版」としない。

スキル定義が利用できる環境では、標準の検証器を実行する：

```bash
node ai-system/report-standards/scripts/validate-dataset.mjs <dataset.json> --metrics <metrics.json>
node ai-system/report-standards/scripts/validate-dataset.mjs <dataset.json> --publish
```

前者は構造と数値の検査であり、人間による法的な最終承認ではない。**構造検証が不合格のときは `--metrics` を付けても集計JSONを出力しない**（`METRICS_NOT_WRITTEN`）。既存の出力ファイルが残っている可能性があるため、後続工程は**必ず終了コードを検査する**（0は成功、非0は不合格）。2026-11-15時点の挙動を確認済み：大崎市パイロットは `--metrics` で issues=0・終了コード0、`--publish` では18件のエラーを出して終了コード1、`fixtures/fictional-city.json` は `--publish` で必ず不合格。

公開には「審査した」というチェックボックスだけでなく、レビュー担当者・レビュー日を `publication.reviewRecord`（`seniorReviewer`／`seniorReviewedAt`／`humanApprover`／`humanApprovedAt`）に記録する。`publication.status` は `draft`／`review`／`approved`。法的論考を含む報告書では、`narrativeClaims`（`kind` は `fact`／`administrative_statement`／`interpretation`／`legal_assessment`）と `legalReviews`（必須8項目：`claimId`・`subjectSeparation`・`taskOwnership`・`publicAuthority`・`privacyAnalysis`・`applicationAndConclusion`・`counterInterpretation`・`seniorReviewed`）が必要。**データ側にSenior review・人間承認記録がない場合、公開判定に合格したと偽らない。** 実際に一次資料を人間が確認した証拠がなければチェック欄だけを埋めない。公開済みのサイト本文とドラフトJSONの承認状況を混同しない。

公開停止条件（正本 `report-standards/README.md` の列挙を維持）：

- 全対象校の学校IDが存在しない、重複がある、12軸に穴がある。
- 出典ID・ページ・対象年度が追えない断定がある。
- `confirmed_yes`／`confirmed_no` なのに直接確認した一次資料がない。
- 機微な学校・保護者・児童情報を匿名化・マスキングしていない。
- 法的結論で主体→事務→公的権限→個人情報→例外の順序が分離されていない。
- 資料なしを適正・違法どちらかと断定している。
- 重要な反証・矛盾を隠す、自治体の説明を無検証で公認と扱う。
- リンクの有効性、引用原文、引用箇所の照合、Senior／humanレビューが未了（**構造検証器の成功のみでは解除できない**）。
- 既存の法令解説・引用・サイト資料・URLを無断変更している。

## 9. 既存資産の保全とサイト接続

- 既存の学校別原本資料：`data/schools/<municipality>/*.json`、`archive/<municipality>/<school>/index.html`

## 11. リポジトリ編集時の固定規律（`AGENTS.md`）

サイトのファイルを触る作業では、スキルの手順に加えて `AGENTS.md` の規律に従う。要点：

- **編集前に3点を明示する**：①対象ファイル ②変更方針 ③変更しない範囲。大規模改修から始めず、必要最小限のファイルだけを変更する。
- 本文の論理をカード・タグ・リンク集に置き換えない。既存の文章を明示的な依頼なしに短くしない。重要な説明・法的整理・行政回答の解説は静的HTML本文を正とする。
- 固有の一次資料、引用元、アンカー、既存URLを不用意に削除・変更しない。生成ファイルを直接修正する前に生成元スクリプトとの関係を確認する。
- **副作用は人間承認なしに実行しない**：メール送信、公開、削除、ファイル書換え、commit、push、merge、deploy、支払、認証情報変更。低コスト層が人間承認要件を解除することも禁止。
- **必須チェック**：`npm test`、`git diff --check`、`git diff --stat`。`npm test` は未加工のチェックアウトに対して実行し、検査前に生成ファイルを自動更新して不整合を隠さない。
- 表示に影響するHTML/CSS/JSを変更した場合はPC幅とスマートフォン幅で主要ページをブラウザ確認する（実務上は1280px／390px／320pxを使っている）。**ブラウザ確認を実施できなかった場合は、実施済みと書かず、その旨を明記する。**
- **完了報告**で、変更ファイル数、変更した内容、変更しなかった範囲、実行したチェック、ブラウザ表示確認の有無を明示する。ZIPを作成した場合は、収録ファイル数、配置場所、変更内容、ブラウザ表示確認の有無を必ず明示する。
- AI運用の正本は `ai-system/`。共通原則は `CORE_INSTRUCTIONS.md`、役割分担は `ORCHESTRATION.md`、完成条件は `QUALITY_STANDARD.md`、Skill選択は `SKILL_REGISTRY.json`。AI運用ルールを別ファイルへ重複定義しない。
- 確信度0.90未満、severityまたはriskが2以上、法令・個人情報・対外公表・金銭判断は下位層で完結させず上位審査へ送る。

### 13-2 文書存否がデータ契約に入っていない

`report-dataset.schema.json` に `documentExistence` 相当のプロパティはなく、検証器も文書存否を検査しない。文書存否は `data/osaki-document-existence-2026.json` という別系統で管理されており、スキーマ版数・検証器・公開ゲートの対象外である。

**対応済み（案）**：同梱の `document-existence.schema.json`（v1.1.0）が別スキーマ案である。`report-dataset.schema.json` には手を付けず、存否台帳を独立したデータ契約として定義した。status は6値（`present_as_standalone_document`／`present_as_provision_only`／`internal_rule_only`／`not_found_in_disclosure`／`not_disclosed`／`formally_determined_nonexistent`）で、`formally_determined_nonexistent` は決定文書・決定日・保有機関・対象年度を揃えないと通らない。`osaki-document-existence-2026-v2.json` はこのスキーマで検証済み（エラー0）。取り込み方法の決定と検証器への組み込みは人間の判断を要する。それまでは、存否台帳の数値を `metrics.json` の数値と同じ扱いで引用しない。

## 14. 他AIの作業手順

1. 最初に正本を読み、対象自治体の公式学校一覧と学校IDを確定。版・年度・変更しない範囲を宣言する（`AGENTS.md` の編集前3点明示）。
2. 開示文書・各学校資料を個々に確認し、出典ID・頁・日付と提出文書の一覧を作成。10種の文書存否も学校ごとに記録する。
3. 全対象校×12軸を一次資料で判定。欠測をNOに変換しない。文書の不提出は独立台帳で明示する。
4. 人権・尊厳への影響、教育委員会の制度責任、学校の実施責任、PTA内部責任を別々に検討。
5. 法的検討は「主体→事務→公法上の権限→個人情報→適用と結論」の順。未確認・反証を残す。
6. 検証器による数値計算（終了コードを検査）、原本照合、プライバシー・法令レビュー、ブラウザ・リンク検証。
7. 自治体評価→学校別評価→原本資料という動線に接続し、既存記事や資料を保護。公開は人間の具体的な承認指示に従う。
8. 完了報告で、変更ファイル数・変更内容・変更しない範囲・実行したチェック・ブラウザ確認の有無を明示する。

**厳禁**：「公立学校とPTAは別だからすべて違法」「委任があるから公務として適法」「入会申込書が開示されなかったから学校もPTAも絶対に保有しない」「未取得資料＝問題なし」「同意があれば個人情報保護の検討は終了」「判定可能校の比率＝全市の違法率」「構造検証に合格したから公開してよい」とすること。
