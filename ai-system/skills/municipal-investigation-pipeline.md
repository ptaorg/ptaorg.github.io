# 自治体総評・調査公開統合スキル v1.0.0（2026-11-16）

## 位置付け
本ファイルは**作業順序と停止条件**のみを規定する。法令審査の正本は `ai-system/skills/municipal-school-report.md` v2.1.0 と `ai-system/report-standards/institutional-rights-framework.json`、12軸・10文書・15法令と表示規格は既存正本を参照し重複定義しない。起動入口は `.agents/skills/pta-municipal-school-report/SKILL.md`。従来の研究ページを新規テンプレートで上書きしない。

## 発動
「○○市の総評」「自治体別PTA評価」「次の市へ」「学校別ページをそろえる」「○○市を公開」等。依頼が短くても、対象の自治体を決めた時点で本手順を先行させる。本文の単純な誤字・余白修正には適用しない。

## 必須工程と成果物
### 0. 対象と版の固定
- 自治体、校種、対象年度、調査基準日、母集団を定義し、既存ページ・生成元・公開履歴を調べる。
- 証拠評価と公開工程を分離。非公開の個人情報・連絡記録を公開リポジトリにアップロードしない。

### 1. 全履歴の探索（最初に実施）
- **接続された全Gmailアカウント**に対し、自治体名、教育委員会名、部署名、学校名、担当メールドメイン、表記揺れを用いて受信・送信・下書き・転送・引用元を探す。`in:anywhere` を使う場合は迷惑メール・ゴミ箱等の検索範囲を明記し、誤検出を選別する。複数アカウントの重複はmessage/thread/内容を照合して除く。
- クエリとアカウント、検索日時、ページトークンの有無、取得した件数、検索制限を台帳に残し、ページネーション完走とスレッド全文・添付の確認を分けて記録する。タイトル／スニペットのみでは「回答原文確認済み」にしない。
- Google Driveも全アクセス可能領域で同名・旧版・資料集・学校別フォルダ・開示決定・PDF・添付保存版を検索し、ページネーション・フォルダ走査を記録。既存サイト・GitHub上の引用とも突合する。
- 全件取得できない場合は `incomplete` とし、未確認対象／期間／理由を記録。未取得を「存在しない」「回答なし」としない。
- **出力A：照会・回答・添付・開示・訂正の時系列台帳と原資料ID台帳**。日付は送信・返信・発行・公表・事実発生を区別。

### 2. 自治体による学校徴収の制度化を探索
- 公式サイト・例規集・教育委員会の公開資料・議会会議録・学校配布物・調達仕様を調査する。探す文書：学校徴収金規則／準公金取扱要綱／公金外現金マニュアル／会計基準／ガイド・手引／委託契約ひな型／保護者同意書／校長宛通知／会費決済システム仕様／旧版・廃止版。
- 絞り込み語は「PTA会費、団体費、学校納入金、学校徴収金、後援会費、委任、受任、委託、同意、一括徴収、口座振替、代理徴収」。サイトに見つからない場合はDrive・Gmailにも戻る。
- 各資料は、発行・制定主体、制定決裁、施行・改正・廃止日、該当条項・ページ、正確な文言、対象校、学校へ伝達された証拠、一次URL、原本閲覧状態を記録。
- **出力B：自治体制度台帳**。個別学校の便宜運用／自治体規範／PTA内部規則を混同しない。
- **最重要警戒項目：**「学校とPTAが委託契約すれば徴収できる」「保護者同意があれば学校が代理徴収できる」等の条件付き許容規定を検出したら、市・教委の制定・指示・監督責任の評価を必須化する。

### 3. 論証順序（逆転禁止）
(1) 学校・教育委員会（公的主体）とPTA（私的団体）の分離 → (2) 入退会・徴収・未納・役員・会計の事務帰属 → (3) 自治体規範の制定・適用・学校所掌事務と**具体的公法上の権限・例外** → (4) 学校が保有する情報について個人情報保護法61条 → 69条（例外の要件を個別に検討） → (5) 教職員の服務・金銭保管・会費契約 → (6) 自由・尊厳・財産・プライバシー・児童の公平と個別救済。
- **制定された規程の存在、学校への適用、上位法上の権限、実際の徴収、適法性を独立に評価**。委任、同意、校長裁量、職専免、慣行を権限の代用としない。
- 行政の回答間・通知間の矛盾、旧版からの転換、事後是正を特定し「行政の主張」「確認した事実」「分析」「未確認」「反証」を分ける。
- PTAの私的行為に憲法の公法上の規定をそのまま直接適用しない。公務権限不存在・権利侵害・国賠・違法を一括認定しない。
- **出力C：制度と学校実務と権利の3層評価、反証表、改善要求**。

### 4. 学校別照合
- 母集団の全学校に既存12軸×10文書台帳を適用し、15法令の個別検討を行う。非開示・未提出・原本不存在決定を混同せず、資料不足の学校を「適正」「違法」と決めない。
- 証拠画像は原資料の頁／匿名化／公開可能性を確認する。学校固有の総評を原資料の直下に示し、長い分析・計算表は下部へ。
- **出力D：全校の評価・資料台帳、分母付き集計、証拠画像掲載判定**。

### 5. サイトと公開品質
- 「全国地図→自治体総評→学校別評価→原資料」の導線を保ち、市の制定責任を学校の責任に転嫁しない。保護者には問題・改善を先に見せ、研究者には出典・審査過程を残す。
- OGP/Xには `og:title`/`og:description`/`og:image`/`twitter:card=summary_large_image` 等を設定。画像URLのHTTP取得、プレビュー表示とキャッシュは**別々に確認**し、X上での実表示未確認なら完了と宣言しない。
- CSSで左右に余白が偏らないこと、PC/モバイルの実ブラウザ表示、地図ピン、検索、学校リンク、原資料URLを確認。変更後の実公開URLで検査する。コミット成功≠デプロイ成功。
- `npm test`、`git diff --check`、`git diff --stat` を実施。実施できない場合は未実施と明示。
- **出力E：変更ファイル一覧、公開ゲート結果、表示・リンク検査ログ**。

## 調査完了と公開の区別
- **A・Bが未調査**なら自治体の正式総評を完成扱いにしない。
- A・Bが調査済でも、原本未照合・各校評価未了・レビュー未承認なら暫定版・一部公開にとどめる。
- クエリを実行しただけでは全履歴確認としない。根拠資料が取得不能なら明示し、何を追加請求するか書く。
- 学校別評価が36校存在することと36校すべて新基準で評価済みであることを混同しない。
- 公開、メール送信、原本破棄などの副作用は指示と承認の範囲でのみ実施。事前承認要件は `AGENTS.md` を優先。

## 起点に使うプログラム
`tools/municipal-audit/cli.mjs` が導入済みなら `plan` で検索計画と入力雛形、`audit` で暫定レポート・CSV・不足ゲートを生成する。**APIへの自動ログインはしない**。Gmail・Driveは接続アプリで検索し、非公開の入力JSONに結果の参照のみ渡す。機械判定は資料真正性・法的結論・公開承認を代替しない。
