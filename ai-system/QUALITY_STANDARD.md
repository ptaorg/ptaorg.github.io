# Quality standard

## 完了条件

成果物は、該当する項目を満たしたときだけ完成扱いにします。

### 調査

- 一次資料を優先した。
- 資料の日付・作成主体・対象期間を確認した。
- 重要な反証または別解釈を確認した。
- 「未確認」を確認済みとして扱っていない。

### 法的整理

- 条文、通知、判例、行政資料を区別した。
- 現行法と旧制度を混同していない。
- 法的事実と独自評価を分けた。
- 重要な断定はSenior reviewを通した。

### サイト記事

- 本文で論理が読める。
- 既存文章を不要に短縮していない。
- 一次資料への導線がある。
- URL・引用・数値を再確認した。
- 補助カードやリンク一覧が本文の代替になっていない。

### サイト編集

- 対象ファイル、変更方針、変更しない範囲が明確。
- 必要最小限のファイルだけを変更。
- 生成元との整合を確認。
- `npm test`, `git diff --check`, `git diff --stat` を原則実施。
- 表示変更時はPC幅とスマートフォン幅を確認。未実施なら明記。

## 失格条件

次のいずれかがあれば完成扱いにしません。

- 存在確認していないURL・法令・判例・資料の断定
- 根拠のない数値
- 実施していないテストや公開確認の虚偽報告
- ユーザーの明示許可なしの大規模な本文削除
- 重要な反証を無視した断定
