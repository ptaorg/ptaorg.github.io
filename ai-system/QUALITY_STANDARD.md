# Quality standard

## 完了条件

成果物は、該当する項目を満たしたときだけ完成扱いにします。

### 調査

- 一次資料を優先した。
- 資料の日付・作成主体・対象期間を確認した。
- 重要な反証または別解釈を確認した。
- 「未確認」を確認済みとして扱っていない。

### 法的整理

- 条文、通知、判例、行政資料を区別した。
- 現行法と旧制度を混同していない。
- 法的事実と独自評価を分けた。
- 重要な断定はSenior reviewを通した。

### サイト記事

- 本文で論理が読める。
- 既存文章を不要に短縮していない。
- 一次資料への導線がある。
- URL・引用・数値を再確認した。
- 補助カードやリンク一覧が本文の代替になっていない。

### サイト編集

- 対象ファイル、変更方針、変更しない範囲が明確。
- 必要最小限のファイルだけを変更。
- 生成元との整合を確認。
- `npm test`, `git diff --check`, `git diff --stat` を原則実施。
- 表示変更時はPC幅とスマートフォン幅を確認。未実施なら明記。

## 失格条件

次のいずれかがあれば完成扱いにしません。

- 存在確認していないURL・法令・判例・資料の断定
- 根拠のない数値
- 実施していないテストや公開確認の虚偽報告
- ユーザーの明示許可なしの大規模な本文削除
- 重要な反証を無視した断定

## 自治体総評のWeb公開完了条件（2026-11-16）

自治体総評のサイト掲載は、調査と法的評価の完了とは独立した工程として `ai-system/skills/municipal-web-publishing.md` を適用する。

- 元本文・学校名・法令根拠・アンカー・学校リンク・証拠画像とその公開属性を保全する。
- DOM / computed style とPC・スマートフォン幅で、余分な右余白、文字の重なり、学校名の欠落、地図の位置、カードの可読性を実測して合否判定する。
- GitHubへのコミット成功・PRマージ・GitHub Pagesへの反映・公開URLの実表示を別状態で記録する。
- OGPの初期HTML・画像のHTTP取得・X上での画像付きカード表示は別の検証項目。プレビュー未実測なら成功宣言しない。
- 全国地図→市総評→学校別評価→一次資料へのリンクを実際に辿る。調査資料が不足している学校を適正済みと表示しない。
- `node scripts/validate-municipal-web.mjs research/<slug>.html` と `npm test` が静的検査の入口。実ブラウザ・外部HTTP・実Xプレビュー・レビュー担当者の記録はテンプレートの公開チェックマニフェストに残す。静的検査通過は公開完了の証明ではない。
